# 부처님 리소스 파이프라인

꾸미기 이미지가 GPT에서 앱까지 가는 길. 새 아이템을 넣거나 기존 것을 다시 받을 때 이 문서대로 한다.

> 2026-10-01 기준 (부처 재질·얼굴/목 슬롯, 모자별 피부 경계 검수 규칙 추가). 머리 아이템에서 세 번 실패하고 네 번째에 자리 잡은 방식이다.
> 지난 방식은 맨 아래 [왜 이렇게 됐나](#왜-이렇게-됐나)에 남겨 두었다.

---

## 한눈에

```
GPT 생성물                 Imgs/  (납품 원본, 사람이 관리)          assets/avatar/  (앱에 나감, 스크립트가 만듦)
─────────                 ─────────────────────────              ──────────────────────────────
몸 · 가사 · 소품 ──배치──▶ base_*.png, acc_*.png …  ──검사·WebP──▶ base_*.webp, acc_*.webp …
모자 쓴 얼굴     ──복사──▶ head_*_face.png          ──정합·자르기─▶ head_*.webp
                                                                 ├─ skin_*.webp  (부처 재질을 입힐 살)
                                                                 └─ thumbs/*.webp (옷장 칸)
```

굽는 순서:

```
python tools/build_avatar_assets.py   # Imgs/ → assets/avatar/
python tools/make_avatar_skins.py     # 몸·머리 레이어에서 살만 → skin_*.webp
python tools/make_avatar_thumbs.py    # 옷장 칸 썸네일
```

**원본은 PNG, 앱에는 WebP.** `Imgs/`는 무손실 PNG로 두고, 스크립트가 WebP(품질 90, `WEBP_QUALITY`)로 구워 `assets/avatar/`에 넣는다.

| | PNG | WebP 품질 90 |
|---|---|---|
| 1024 레이어 한 장 | 300~430KB | 20~80KB |
| 지금 23장 전체 | 3.4MB | 0.67MB |
| 화질 | | 합성 결과 평균 차이 0.65/255. 2배 확대해도 구분 안 됨 |

알파(투명도)는 무손실로 남아서 윤곽이 뭉개지지 않는다.

| 폴더 | 누가 쓰나 | 빌드에 들어가나 | 손으로 고쳐도 되나 |
|---|---|---|---|
| `Imgs/` | 사람 | **아니오** (`pubspec.yaml`에 없음) | 새 파일 추가만. **덮어쓰지 않는다** |
| `assets/avatar/` | 스크립트 | 예 | 아니오. 스크립트를 다시 돌린다. **PNG를 넣지 않는다** — 폴더째 번들되므로 남은 PNG는 그대로 APK에 들어간다. 스크립트가 같은 이름 PNG를 지운다 |
| `assets/avatar/thumbs/` | 스크립트 | 예 | 아니오 |
| `assets/avatar/skin_*.webp` | 스크립트 (`make_avatar_skins.py`) | 예 | 아니오 |

## 규칙 세 가지

1. **모든 레이어는 1024×1024, 같은 좌표계.** 앱은 레이어를 같은 크기 상자에 `BoxFit.contain`으로 겹치기만 한다. 코드([buddha_figure.dart](../lib/features/avatar/buddha_figure.dart))에서 아이템별로 위치를 옮기지 않는다. 어긋나면 에셋이 틀린 것이다.
2. **머리 아이템은 「모자 쓴 얼굴」로 받는다.** 모자만 따로 그리면 머리에 씌울 수가 없다. 뚜껑처럼 얹히거나 이마를 덮는다.
3. **`Imgs/`의 원본은 덮어쓰지 않는다.** 다시 받으면 새 이름으로 넣고, 확인한 뒤 바꾼다.

## 겹치는 순서

[avatar_equip.dart:5](../lib/features/avatar/avatar_equip.dart#L5)의 `AvatarSlot` 순서가 곧 그리는 순서다.

```
후광(halo) → 대좌(seat) → 몸·가사(robe) → 발(feet) → 머리(head) → 얼굴(face) → 목(neck) → 입(mouth)
```

- 입은 맨 마지막이다. 풍선껌 풍선은 입에서 앞으로 부풀어 안경 아래 테나 헤드폰보다 앞에 있다.
- **후광만 예외로 키우고 올려 그린다.** 머리가 커서 1024 캔버스 안의 후광은 많이 가리는데, 캔버스 안에서 키우거나 올리면 위가 잘린다. 그래서 앱이 후광 레이어를 두 눈 가운데 `(510, 356)`을 중심으로 1.2배 키우고 60px(1024 좌표) 올려 그림 상자 위로 넘치게 그린다([halo_spin.dart](../lib/features/avatar/halo_spin.dart)의 `kHaloScale`·`kHaloLift`, `HaloFrame`).
  - 후광 미리보기·비교표도 같은 변환을 해야 앱과 같다. 굽는 레이어 자체는 바꾸지 않는다.
  - 스크롤 목록처럼 넘친 부분을 자르는 곳에서는 부처님 위에 `size * kHaloOverflow`만큼 비워 둔다(프로필).

- 발은 몸 바로 다음이다. 재질을 입으면 몸 위에 물든 살(`skin_body`)이 한 번 더 겹치는데, 신발이 그보다 뒤에 그려져야 물든 맨발을 덮는다.

- 「부처」(buddha) 슬롯은 겹칠 그림이 없다. 재질을 고르면 몸·머리 레이어 **바로 위에** 살 레이어(`skin_*`)를 물들여 한 번 더 겹친다. 아래 [부처 재질](#부처-재질) 참고.
- 예전 「악세서리」 슬롯은 얼굴(안경)·목(단주)으로 나뉘었다. 저장본은 아이템 id로 슬롯을 찾으므로 예전 값도 제자리로 간다.
- 가사를 안 입는 상태는 없다. 비어 있으면 `robe_saffron`을 그린다. 부처가 비어 있으면(예전 저장본) 살빛 부처다.
- 민머리(`head_shaved`)는 레이어가 없다. 몸 그림의 머리가 곧 민머리다.
- 머리 레이어는 목(y=478)에서 잘려 있다. 그 아래는 몸 레이어가 보인다.

## 새 머리 아이템 넣기

예시: 「연꽃 관」을 `head_lotus`로 넣는다.

### 1. GPT에게 받기

[부처님_머리_얼굴_GPT프롬프트.md](부처님_머리_얼굴_GPT프롬프트.md)의 프롬프트를 쓴다. 받을 것은 한 장이다.

| 파일 | 내용 | 필수 |
|---|---|---|
| `head_lotus_face.png` | 연꽃 관을 쓴 얼굴. 목까지만 | 필수 |
| `head_lotus_item.png` | 관만 따로 | 선택. 없으면 얼굴에서 떼어 낸다 |

`Imgs/`에 저장한다. **다시 받을 때는 기존 파일을 덮어쓰지 않고** `head_lotus_face_v2.png`처럼 번호를 붙인다. 빌드와 `--measure`는 가장 높은 번호를 쓴다(`face_source()`).

### 2. 위치 값 재기

```
python tools/build_avatar_assets.py --measure head_lotus
```

얼굴의 두 눈과 귀를 찾아 베이스 얼굴에 겹치는 `(배율, 왼쪽, 위)`를 계산한다. 출력 예:

```
베이스 눈 (510, 350) 귀폭 462
head_lotus 눈 (625, 716) 귀폭 759 → 배율 0.609
비침이 적은 순:
  (0.614, 126, -90)  비침 99px
  ...
FACE_FIT 에 넣을 값:
    "head_lotus": (0.614, 126, -90),
```

- **비침**은 새 얼굴 밖으로 삐져나오는 베이스 민머리의 픽셀 수다. 목 이음매 탓에 수십~백 px 정도는 나온다. 화면에서는 안 보인다.
- **400px을 넘으면** GPT 얼굴이 베이스와 너무 다른 것이다. 값을 억지로 맞추지 말고 다시 받는다.
- 귀 폭은 눈 높이가 아니라 **눈보다 조금 아래(눈 간격의 0.3배)**, 귓불 쪽에서 잰다. 눈 높이에서 재면 버킷햇처럼 처진 챙이 같이 잡혀 배율이 작게 나온다(`EAR_BELOW_EYES`).
- 비침은 얼굴이 클수록 무조건 줄어든다. 맨 위 결과가 탐색 범위 끝(출발 배율 ±0.03)에 붙어 있으면 출발 배율이 틀린 것이다. 비침만 보고 배율을 키우지 말고, 합성해서 **베이스 귀가 새 귀 밖으로 비치는지**를 본다.
- `눈을 못 찾았다`가 나오면 눈이 감은 새까만 선이 아니거나, 눈 위아래가 살색이 아닌 것이다(모자가 눈썹까지 내려온 경우 등). 다시 받는다.

### 3. 등록

| 파일 | 할 일 |
|---|---|
| [build_avatar_assets.py](../tools/build_avatar_assets.py) | `FACE_FIT`에 2단계 값 추가, `HEADS`에 이름 추가 |
| [make_avatar_thumbs.py](../tools/make_avatar_thumbs.py) | `HEADS`에 이름 추가 |
| [avatar_equip.dart](../lib/features/avatar/avatar_equip.dart) | `kWardrobe`에 `WardrobeItem(id: 'head_lotus', name: '연꽃 관', slot: AvatarSlot.head, meritCost: …, skin: 'skin_head_lotus')` — `skin`을 빠뜨리면 돌부처가 그 모자를 쓸 때 얼굴만 살빛으로 남는다. 테스트가 잡는다 |

`pubspec.yaml`은 폴더 단위로 등록돼 있어서 건드리지 않아도 된다.

### 4. 굽기

```
python tools/build_avatar_assets.py
python tools/make_avatar_skins.py
python tools/make_avatar_thumbs.py
```

출력에 `head_lotus  (모자 쓴 얼굴을 베이스에 포갬, 비침 99px)`와 `skin_head_lotus`가 나오면 된다.

### 5. 확인

- 에뮬레이터 꾸미기 탭에서 씌워 본다. **이마와 백호(이마 가운데 주황 점)가 보이는지**, 목 이음매에 선이 없는지 본다.
- 가사 4종을 번갈아 입혀 본다. 머리 레이어는 목 위만 있으니 가사 색과 상관없어야 한다.
- 옷장 칸 썸네일에 얼굴이 섞여 나오지 않는지 본다. 섞여 나오면 `head_lotus_item.png`를 받아 넣는다.
- **핑꾸·돌·옥부처를 모두 입혀 본다.** 얼굴만 재질색이 되고 모자는 제 색이어야 한다. 특히 핑꾸부처처럼 피부와 차이가 큰 색이 1px짜리 비침도 가장 잘 드러낸다.
- 결과를 3~4배 확대해 **챙 중앙 바로 아래, 양쪽 관자놀이, 귀 위쪽, 모자 바깥 윤곽**을 각각 본다. 모자 둘레에 살빛 띠가 남거나 모자 일부가 재질색이 되면 `skin_head_*` 경계가 틀린 것이다.

### 6. 모자와 피부 경계 규칙

`skin_head_*`도 앱에 납품되는 제품 이미지다. 스크립트가 오류 없이 끝났다고 완성된 것이 아니며, 반드시 실제 합성 결과를 눈으로 확인한다.

1. **비교할 단계를 나눈다.** `Imgs/head_*_face.png` 원본 → `assets/avatar/head_*.webp` 정합 결과 → `skin_head_*.webp` 마스크 → 앱과 같은 순서로 합성한 최종 이미지를 차례로 본다. 마스크만 보면 모자 아래의 얇은 틈을 놓칠 수 있다.
2. **전역 임계값 하나로 모든 모자를 처리하지 않는다.** 대나무·밀짚·갈색 모자는 피부색과 색이 가까워 색 차이와 침식(`erode`)만으로 정확히 나뉘지 않는다. `make_avatar_skins.py`의 `HAT_ERODE`와 `FOREHEAD_SEAM`에 모자별 값을 둔다.
   - **챙이 처진 모자(버킷햇)**는 챙 그늘에 든 이마가 어두워 통째로 모자로 분류된다. `FOREHEAD_SEAM`으로 범위를 넉넉히 잡고, 실제 경계는 `SKIN_COLOR`(색상·채도·명도)로 가른다. 버킷햇은 살 색상 14~20, 카키 챙 24~30이라 색상 21 이하를 살로 본다. 챙 안쪽 그늘은 명도 120 미만이라 모자로 남는다.
3. **침식을 무작정 키우지 않는다.** 살색 띠를 없애려고 전체 마스크를 많이 깎으면 모자 챙까지 피부 재질색으로 물든다. 먼저 실제 이마 경계를 따라 `FOREHEAD_SEAM` 곡선을 조정하고, 침식은 가장자리의 작은 잔여 픽셀만 없애는 데 쓴다.
4. **피부 보정 범위는 민머리 윤곽 안으로 제한한다.** `head_limit` 밖의 모자 외곽과 챙은 어떤 부처 재질에서도 원래 색을 지켜야 한다.
5. **피부색과 비슷한 모자는 형상과 색을 함께 쓴다.** 삿갓처럼 중앙 챙 아래에 살색과 비슷한 픽셀이 남는 경우, 이마 경계 곡선과 HSV 색상 마스크를 함께 적용한다. 중앙부만 남으면 전체 값을 바꾸지 말고 해당 곡선의 y 좌표를 몇 픽셀 단위로 조정한다.
6. **사용자가 표시한 픽셀을 기준으로 고친다.** 스크린샷에 원이나 화살표가 있으면 그 영역을 먼저 확대해 원본 모자색, 피부색, 최종 재질색을 비교한다. 다른 경계를 추측해 고치지 않는다.

합격 조건:

- 의도한 이마 경계 아래에는 원래 살색 픽셀이 남지 않는다.
- 모자 바깥 윤곽과 챙은 핑크·돌·옥 재질을 적용해도 원래 모자색이다.
- 이마의 백호와 양쪽 귀가 가려지거나 잘리지 않는다.
- 수정 뒤 `build_avatar_assets.py` → `make_avatar_skins.py` → `make_avatar_thumbs.py` 순서로 다시 굽고 테스트한다. 머리 정합이나 원본이 바뀌었는데 피부 레이어만 예전 것을 쓰면 안 된다.

## 새 얼굴 · 목 · 대좌 · 후광 아이템 넣기

이쪽은 머리와 달리 **물건만 따로** 받아도 된다. 캐릭터와 겹치는 면이 작아서다. 살이 없으니 살 레이어도 필요 없다.

| 슬롯 | 무엇 | 파일명 |
|---|---|---|
| 얼굴 `face` | 안경, 선글라스, 반창고처럼 얼굴 앞에 붙는 것 | `acc_*` |
| 목 `neck` | 단주, 목걸이, 목도리처럼 목·가슴에 걸리는 것 | `acc_*` |
| 발 `feet` | 신발, 버선처럼 발을 덮는 것. 비울 수 있다(맨발이 기본) | `feet_*` |
| 대좌 `seat` · 후광 `halo` | 뒤에 깔리는 것 | `seat_*`, `halo_*` |

### 지금 방식 — `PLACED` (2026-10-01부터)

물건 원본을 `Imgs/`에 그대로 두고, [build_avatar_assets.py](../tools/build_avatar_assets.py)가 굽는 단계에서 베이스 위 제자리로 옮긴다.

```python
PLACED = {
    # 이름: (따라갈 앵커, 배율, 원본 기준점, 베이스 기준점, 몸 뒤로 숨길 곳)
    "acc_sunglasses": ("eyes", 156 / 452 * 0.94, (512, 515), (510, 356), ()),
    "acc_neckphones": ("neck", 0.34, (512, 477), (512, 470), ("band", "hands")),
    "feet_sneakers": ("feet", 128 / 336, (511, 776), (511, 936), ("robe",)),
    ...
}
```

- **원본 기준점이 베이스 기준점에 오도록** 비율을 지킨 채 줄인다. 가로세로를 따로 늘리지 않는다.
- 베이스 기준점(1024 좌표): 감은 두 눈 가운데 `(510, 356)` · 두 눈 간격 156 · 목 y 478 · 합장한 손끝 y 520 · 두 발 중심 x 457/565 · 발바닥 y 918.
- 값은 `base_saffron.png` 위에 미리보기 합성을 몇 번 해 보며 정한다. 정한 이유를 `PLACED` 위 주석에 적는다.
- **따라갈 앵커**를 함께 적는다. 얼굴 앞 → `eyes`, 입 → `mouth`, 목·가슴 → `neck`, 발 → `feet`. 다른 캐릭터에는 이 앵커를 따라 옮겨진다. 아래 [캐릭터 앵커](#캐릭터-앵커).
- 원본 둘레의 투명도 1~15짜리 흐린 점(GPT 출력에 수천 개씩 있다)은 지운다(`ALPHA_FLOOR`).

**몸 뒤로 숨길 곳** — 소품 레이어는 몸보다 위에 그려지므로, 몸 뒤로 가야 할 부분은 소품에서 지운다.

| 값 | 지우는 곳 | 쓰는 소품 |
|---|---|---|
| `"hands"` | 합장한 두 손 (`HAND_OUTLINE` 다각형 ∩ 살) | 헤드폰 컵, 금빛 단주 |
| `"band"` | 헤드폰 원본의 밴드 (`BAND` 다각형, 원본 좌표) | 헤드폰 — 밴드는 목 뒤로 |
| `"robe"` | 가사 영역 (가사 원본끼리 다른 픽셀) | 운동화 — 밑단이 신발 위를 덮는다 |
| `"chin"` | 목 자르는 줄(y 478)보다 위의 살 = 턱 | 턱받이 — 턱 위로 올라온 뒤쪽 목둘레가 턱 뒤로 간다 |

- 가사 영역에는 발가락 윤곽선과 밑단 아래 발등 그림자도 섞여 잡힌다(가사마다 그림자 색이 조금씩 달라서다). 그대로 쓰면 그 자리 신발이 지워져 발가락이 비친다. 열림 연산으로 가는 선을 걸러 내고 안쪽으로 7px 더 깎아서, 신발이 밑단 아래로 살짝 파고들게 한다.
- 손 영역을 사각형으로 잡으면 맨살인 왼쪽 가슴까지 들어가 헤드폰 컵에 구멍이 난다. 반드시 손 윤곽을 따른다.
- 운동화 두 짝 사이 위쪽은 발목이 가늘어 맨발이 비친다. 어두운 중간색(`SHOE_GAP_SHADOW`)으로 메운다. 가사 색을 따면 다른 가사에서 어긋난다. 발이 10px 넘게 비치면 빌드가 멈춘다.
- 썸네일은 지우기 전의 물건 원본에서 뽑는다. 앱 레이어는 손 뒤·목 뒤가 지워져 잘려 보이기 때문이다.

등록할 곳: `PLACED`(위치) · `kWardrobe`(슬롯·공덕). 썸네일 스크립트는 `PLACED`를 그대로 읽는다.

- 물건 원본은 1024가 아니어도 된다(정사각이면 된다). 배율로 줄여 놓는다.
- 원본을 고쳐야 하면 덮어쓰지 않고 `acc_cucumber_v2.png`처럼 번호를 붙인다. 빌드와 썸네일은 가장 높은 번호를 쓴다(`latest_source()`). 예: 오이 팩은 두 조각 간격이 좁아 조각만 떼어 벌린 v2 를 쓴다.
- **움직이는 아이템**(풍선껌)은 그림 두 장을 둘 다 `PLACED`에 넣는다. 두 번째 그림(`mouth_bubblegum_popped`)은 옷장 아이템이 아니라 `MOTION_ONLY`에 넣어 썸네일을 만들지 않고, `kWardrobe`에서 `popped:`로 연결한다.

### 움직이는 아이템 — 풍선껌

[bubble_gum_motion.dart](../lib/features/avatar/bubble_gum_motion.dart). 그림을 여러 장 받지 않고, 풍선과 터진 껌 두 장을 **입 `(510, 396)`을 중심으로 키우고 줄이기만** 한다. 레이어 사각형은 다른 레이어와 같으므로 정렬 규칙(레이어별 위치 보정 금지)을 깨지 않는다.

```
부풀기 0~2.1초 → 터짐 ~2.24초 → 붙은 껌 ~3.85초 → 빨아들임 ~4.34초 → 쉼 ~7초 → 반복
```

| 화면 | `AvatarMotion` | 보이는 것 |
|---|---|---|
| 절 | `loop` | 7초마다 반복 |
| 꾸미기 | `once` | 한 바퀴 돌고 다 부푼 풍선에서 멈춤 |
| 옷장 썸네일 · 그 밖 | `still` | 다 부푼 풍선 한 장 |
| 기기 「동작 줄이기」 켜짐 | (무시) | 다 부푼 풍선 한 장 |

시점별 크기·투명도는 `BubbleGumFrame.at()` 한 곳에서 계산하고 테스트로 고정해 두었다. 타이밍을 바꾸려면 거기 구간 값만 고친다.

### 예전 방식 — `assemble_buddha_sprites.py`

염주·안경·연꽃 대좌·후광 4종은 이 방식으로 만들었다. 새 아이템에는 쓰지 않는다.

1. GPT에게 물건만, 투명 배경으로 받는다.
2. [assemble_buddha_sprites.py](../tools/assemble_buddha_sprites.py)의 `ITEMS`에 `(원본 경로, 너비, 높이, 가운데 x, 위 y)`를 넣고 돌린다. 1024 캔버스의 제자리에 놓인 그림이 `Imgs/`에 생긴다.
   - 너비·높이·위치는 베이스에 겹쳐 보며 손으로 정한다. 지금 값: 염주 188×158 @ y470, 안경 258×90 @ y315, 연꽃 대좌 620×210 @ y804, 후광 560×560 @ y20.
3. [build_avatar_assets.py](../tools/build_avatar_assets.py)의 `OVERLAYS`(이름 → 따라갈 앵커), [make_avatar_thumbs.py](../tools/make_avatar_thumbs.py)의 `ITEMS`, `kWardrobe`에 등록하고 굽는다. `kWardrobe`에서는 슬롯을 위 표대로 고른다.

> **주의** — `assemble_buddha_sprites.py`의 원본 경로(`GEN`)는 이 PC의 Codex 생성 폴더를 가리킨다. 저장소에는 없다.
> 다른 PC에서는 이 스크립트를 못 돌린다. **`Imgs/`에 있는 배치 결과가 정본이다.**
>
> 같은 스크립트의 `build_heads()`는 예전 방식(모자만 늘려 얹기)으로 `Imgs/head_*.png`를 다시 쓴다.
> 앱 빌드는 `head_*_face.png`를 먼저 쓰므로 결과에는 영향이 없다. 하지만 헷갈리니 새 머리 아이템을 `HEAD_ITEMS`에 넣지 않는다.

## 새 가사 넣기

가사는 몸 전체 그림(`base_*.png`)이 통째로 바뀐다.

1. GPT에게 `base_saffron.png`를 주고 **가사 색만 바꾼** 전신을 받는다.
2. `assemble_buddha_sprites.py`의 `BASE_VARIANTS`에 넣고 돌린다. 받은 그림을 베이스 외곽에 맞추고, **가사 영역만** 새 그림에서 가져온다. 얼굴·손·발은 원본 픽셀 그대로 남는다.
   - 가사 영역을 고르는 색 조건이 색마다 다르다(`make_cloth_mask`). 새 색이면 조건을 추가해야 한다.
3. `BASES`, `ROBES`, `kWardrobe`에 등록한다. `kWardrobe`에서는 `file:`로 파일명을 알려 주고(`robe_ash` → `base_ash`), `skin: 'skin_body'`를 붙인다.
4. `make_avatar_skins.py`를 다시 돌린다. 살 레이어는 **가사끼리 픽셀이 같은 곳**을 살로 본다. 2단계에서 얼굴·손·발을 원본 그대로 두었으니 새 가사가 늘어도 살은 그대로여야 한다. 살이 크게 줄면 스크립트가 멈춘다(`MIN_BODY_SKIN`).

## 부처 재질

「부처」 슬롯은 부처님의 살을 돌·백자·옥·황금 같은 재질로 바꾼다. **그림을 새로 받지 않는다.**

### 어떻게 그려지나

```
base_saffron.webp           ← 가사·살 원래 그대로
skin_body.webp   (물들임)   ← 살만. 재질 색으로 칠해 위에 덮는다
head_straw.webp             ← 모자·얼굴 원래 그대로
skin_head_straw.webp (물들임) ← 얼굴만
acc_glasses.webp            ← 소품은 제 색
```

- 살 레이어는 [make_avatar_skins.py](../tools/make_avatar_skins.py)가 만든다.
  - `skin_body` — 가사 5종이 서로 같은 픽셀. 가사가 늘어도 한 장.
  - `skin_head_*` — 머리 레이어에서 모자를 뺀 나머지. 기본 분리는 `extract_item`과 같은 원리를 쓰되, 넓은 챙이나 피부색과 비슷한 모자는 `HAT_ERODE`·`FOREHEAD_SEAM`·색상 마스크로 모자별 경계를 보정한다.
- 물들이는 건 앱의 `ColorFilter.matrix`다. 살의 밝기를 어두운 색 → 밝은 색 사이로 옮긴다. 음영은 밝기에 남아 있어 입체감이 산다. 볼 홍조는 사라지는데, 불상이라 오히려 맞다.

### 새 재질 넣기

코드 한 곳이다. [avatar_equip.dart](../lib/features/avatar/avatar_equip.dart)의 `kWardrobe`에 `slot: AvatarSlot.buddha` 아이템을 추가하고 `SkinTint(dark: [...], light: [...])`를 준다.

- `dark` — 살의 가장 어두운 곳(밝기 90)이 될 색.
- `light` — 살의 가장 밝은 곳(밝기 235)이 될 색. **255보다 크게 잡아도 된다.** 그 채널이 밝은 곳에서 먼저 하얗게 차서 번쩍이는 느낌이 난다(황금의 R·G, 백자의 전 채널).
- `file: 'head_shaved'`, `hasLayer: false` — 옷장 칸에는 민머리 썸네일을 그 재질로 물들여 보여준다.

값을 고를 때는 에뮬레이터 꾸미기 탭에서 가사 4종·머리 3종과 번갈아 입혀 본다.

### 안 되는 것

- **청동·은처럼 광택으로 읽히는 금속.** 밝기를 색으로 옮기는 것만으로는 하이라이트가 안 생겨서 갈색·회색 피부처럼 보인다. 피부색으로 오해받을 수 있어 넣지 않았다. 하려면 반사광 텍스처를 겹치거나 셰이더를 써야 한다.
- **돌 결·옥 무늬 같은 질감.** 색만 바뀐다. 질감이 필요하면 살 레이어 모양대로 오린 질감 이미지를 한 장 더 겹치는 방식으로 넓힌다.
- **재질에 따라 모자·소품이 같이 바뀌는 것.** 일부러 막았다. 아이템은 제 색을 지킨다.

## 썸네일이 만들어지는 방식

[make_avatar_thumbs.py](../tools/make_avatar_thumbs.py) — `assets/avatar/*.webp`를 읽기만 하고 192×192 WebP로 뽑는다. 입력이 손실 압축본이지만 썸네일 품질 차이는 없었다.

| 종류 | 방식 |
|---|---|
| 가사 | 목 아래만 자른다(`ROBE_CROP`). 얼굴이 보이면 옷이 아니라 캐릭터로 읽힌다 |
| 민머리 | 머리까지만 자른다(`SHAVED_WINDOW`) |
| 머리 아이템 | `_item.png`가 있으면 그것. 없으면 머리 레이어를 민머리와 비교해 **달라진 부분 중 맨 위 덩어리**만 남기고, 살 레이어(`skin_head_*`)를 한 번 더 뺀다. 그래서 `make_avatar_skins.py` 다음에 돌린다 |
| `PLACED` 소품 | `Imgs/`의 물건 원본에서 흐린 점을 지우고 잘라 가운데에 놓는다 |
| 나머지 | 불투명 영역을 잘라 가운데에 놓는다 |

머리 아이템을 떼어 낼 때 기준값(`threshold=45`)을 낮추면 챙 아래 이마가 띠처럼 딸려 나온다.

## 빌드에서 `Imgs/`가 빠지는지

`pubspec.yaml`의 `assets:`에는 `assets/avatar/`와 `assets/avatar/thumbs/`만 있다. `Imgs/`는 저장소에만 있고 앱에는 들어가지 않는다. 확인하려면:

```
unzip -l build/app/outputs/flutter-apk/app-release.apk | grep -c "avatar/.*\.webp"   # 27 (레이어 11 + 살 4 + 썸네일 12)
unzip -l build/app/outputs/flutter-apk/app-release.apk | grep -c "avatar/.*\.png"    # 0  (남은 PNG 없음)
unzip -l build/app/outputs/flutter-apk/app-release.apk | grep -c "Imgs/"              # 0
```

## 왜 이렇게 됐나

| 시도 | 방식 | 결과 |
|---|---|---|
| 1 | 모자만, 1024 캔버스의 제자리에 그려 받기 ([스프라이트_작업요청서](부처님_스프라이트_작업요청서.md)) | 모자가 머리보다 훨씬 크고 낮다. 챙이 눈 바로 위(y278)까지 내려와 이마와 백호를 덮는다. 위로 올릴 여유도 8px뿐 |
| 2 | 모자만 받아 스크립트로 크기를 줄여 머리 위에 얹기 (`build_heads()`) | 모자가 머리를 덮지 못하고 정수리 위에 뚜껑처럼 올라앉는다 |
| 3 | 베이스 전신을 마스크 편집해 받기 ([머리_재작업요청서](부처님_머리_재작업요청서.md)) | 이 방식의 전신(`_full.png`)은 들어오지 않았다. `build_avatar_assets.py`에 처리 경로만 남아 있다 |
| **4** | **모자 쓴 얼굴만 받아 눈·귀로 베이스에 맞추기** | **지금 방식.** 모자가 머리에 자연스럽게 씌워지고, 얼굴 그림이 달라도 목 위만 쓰니 이음매가 안 보인다 |

핵심은 **모자와 머리를 한 번에 그려야 한다**는 것이다. 모자를 따로 그리면 그 모자가 이 머리에 맞는지 GPT도 우리도 알 수 없다.

## 캐릭터 앵커

> 2026-10-06. 여성·손오공·어른 부처처럼 **비율이 다른 캐릭터**에도 소품을 한 번만 그려 쓰기 위한 준비. 지금 앱에는 동자 부처 하나뿐이다.

메이플스토리가 몸 그림마다 「목은 여기, 눈썹은 여기」를 두고 아이템을 그 점에 붙이듯, 캐릭터마다 기준점(앵커) 여섯 개를 둔다. 소품은 **기준 캐릭터(동자 부처) 위에서 한 번 자리를 정하고**, 다른 캐릭터에는 두 캐릭터의 앵커를 따라 옮기고 키워서 굽는다.

| 앵커 | 점 | 단위 길이 | 따라가는 소품 |
|---|---|---|---|
| `eyes` | 감은 두 눈의 가운데 | 두 눈 사이 거리 | 안경, 선글라스 |
| `mouth` | 입(검은 곡선)의 가운데 | 두 눈 사이 거리 | 풍선껌 |
| `head` | 감은 두 눈의 가운데 | 귓불 높이의 귀 끝~귀 끝 폭 | 후광 |
| `neck` | 목이 가장 좁은 줄, 얼굴 가운데 선 위 | 그 줄의 폭 | 단주, 헤드폰 |
| `feet` | 두 발 가운데, 발바닥 | 두 발 중심 사이 거리 | 운동화 |
| `body` | 몸 가운데, 맨 아래 | 몸 전체 폭 | 대좌 |

새 캐릭터의 `eyes` 단위가 기준의 1.2배면, 눈에 붙는 소품도 1.2배가 되고 눈에서 떨어진 거리도 1.2배가 된다.

### 어디에 있나

| 파일 | 내용 |
|---|---|
| [tools/characters/dongja.json](../tools/characters/dongja.json) | 동자 부처의 앵커, 머리 자르는 높이(`neck_cut_y`), 합장한 손 윤곽(`hand_outline`) |
| [tools/avatar_anchors.py](../tools/avatar_anchors.py) | 앵커 자동 측정, 캐릭터 사이 옮기기(`map_placement`) |
| [build_avatar_assets.py](../tools/build_avatar_assets.py) | `PLACED`·`OVERLAYS`에 앵커 이름. `place_item`·`place_overlay`가 대상 캐릭터를 받는다 |

### 재기

```
python tools/avatar_anchors.py          # 동자 부처를 다시 재서 JSON 과 비교
python tools/avatar_anchors.py adult    # 다른 캐릭터 (characters/adult.json 의 base 그림을 잰다)
```

- 앵커는 전부 몸 그림(`base_*.png`)에서 자동으로 잰다. 눈은 머리 정합(`--measure`)과 같은 방식이다.
- 출력 끝의 JSON 조각을 `characters/<id>.json`의 `anchors`에 넣는다.
- 3px·2% 넘게 다르면 멈춘다. 몸 그림을 다시 받았으면 JSON 을 고친다.

### 지켜지는 것

- **기준 캐릭터는 옮기지 않는다.** `map_placement`가 계산 없이 값을 그대로 돌려준다. 앵커를 들이면서 다시 구운 48장이 이전과 픽셀까지 같았다.
- **앱에서는 여전히 위치를 옮기지 않는다.** 옮기는 건 굽는 단계다. 「레이어별 위치 보정 금지」 규칙은 그대로다.
- 앱이 직접 쓰는 기준점(풍선껌의 입 `kMouthAnchor`)은 `dongja.json`의 입 앵커와 같은지 [avatar_anchor_test.dart](../test/avatar_anchor_test.dart)가 본다.

### 검증

동자 부처를 82%로 줄이고 옮긴 가짜 캐릭터로 확인했다(2026-10-06).

- 자동 측정: 점은 1px 안, 단위는 목만 2.4%(가장 좁은 한 줄을 고르는 방식이라), 나머지는 1% 안.
- 후광·대좌·선글라스·안경·헤드폰(손 뒤로 숨김 포함)·금빛 단주·단주·풍선껌·운동화가 모두 제자리에 붙었다.

### 새 캐릭터를 들일 때 남은 일

앵커는 소품을 옮기는 데까지다. 캐릭터를 실제로 앱에 넣으려면:

1. **몸 그림** — 가사 색마다 한 장씩(`base_*`). 얼굴·손·발은 가사끼리 같은 픽셀이어야 한다(살 레이어·가사 마스크가 그 차이로 만들어진다).
2. **`characters/<id>.json`** — 앵커는 재고, `neck_cut_y`와 `hand_outline`은 사람이 정한다.
3. **모자** — 캐릭터마다 「모자 쓴 얼굴」을 새로 받는다. 머리 모양을 감싸야 해서 앵커로 못 옮긴다. `--measure`가 그 캐릭터의 몸 그림에 맞추도록 넓혀야 한다.
4. **스크립트** — 지금 `main()`은 동자 부처만 굽는다. 캐릭터별 출력 폴더(`assets/avatar/<id>/`)로 굽는 반복을 넣는다. 썸네일은 공용 한 벌을 그대로 쓴다.
5. **앱** — 캐릭터 선택, 캐릭터별 에셋 경로, 저장본에 캐릭터. 구매는 아이템 id 로 공유된다. `kMouthAnchor`처럼 앱이 쓰는 기준점은 캐릭터별로.
6. **손오공** — 귀가 작아 `head` 앵커(귀 폭)와 모자 정합 기준을 따로 정해야 한다.
