# 다국어(로컬라이제이션) 가이드

## 어디에 무엇이 있나

| 무엇 | 위치 | 비고 |
|---|---|---|
| 화면 문자열 테이블 | `lib/l10n/app_ko.arb` | 한국어가 원본(템플릿). 키마다 `@키.description` 에 번역가용 설명 |
| 생성 코드 | `lib/l10n/app_localizations*.dart` | `flutter gen-l10n` 이 만든다. 직접 고치지 않는다 |
| 입구 | `lib/l10n/l10n.dart` | 위젯 안 `context.l10n.키`, 컨텍스트 없는 곳 `L.current.키` |
| 긴 콘텐츠(대화·말씀·테스트 등) | `assets/content/<언어>/*.json` | 없는 언어는 `ko/` 로 대체된다 (`content_locale.dart`) |
| Android 앱 이름 | `android/app/src/main/res/values/strings.xml` | 다른 언어는 `values-<언어>/strings.xml` |
| iOS 지원 언어 | `ios/Runner/Info.plist` 의 `CFBundleLocalizations` | |

## 문자열을 새로 쓸 때

1. `app_ko.arb` 에 키와 `@키` 설명을 더한다. 키 이름은 기능 접두사 + 뜻 (`sessionDoneTitle`).
2. 바뀌는 부분은 `{placeholder}` 로. 문장을 조각내 `+` 로 잇지 않는다 (언어마다 어순이 다르다).
3. 한국어 조사가 앞 단어 따라 바뀌면 조사를 따로 넘긴다: `"{name}{particle} …"` + `particleOf()` / `roOf()`.
4. `flutter gen-l10n` (또는 `flutter run`/`pub get` 때 자동).

`test/l10n_test.dart` 가 `lib/` 코드에 한글 문자열 리터럴이 새로 생기면 실패시킨다.

## 저장값과 화면 표기

DB 에 저장되거나 조회 키로 쓰는 값은 언어와 상관없이 한국어(또는 id) 그대로 둔다.
화면에 보일 때만 테이블을 거친다.

- 법명: 저장 `무념` → 화면 `dharmaNameLabel()` (`ordinationNameMunyeom`)
- 법명 글자: 저장 `관`/`견` → 화면 `dharmaSyllableLabel()`, `dharmaComposedName()`
- 번뇌 종류, 고민 칩, 아이템 등은 영문 id 로 저장되고 이름은 getter 가 테이블에서 찾는다.

## 새 언어를 더할 때 (예: 영어)

1. `lib/l10n/app_en.arb` — `{"@@locale": "en", ...}` 에 같은 키로 번역. 빠진 키는 `build/l10n_untranslated.json` 에 목록이 나온다.
   복수형은 번역 파일에서 `{count, plural, =1{1 merit} other{{count} merits}}` 처럼 쓸 수 있다.
2. 콘텐츠: `assets/content/en/` 에 같은 이름의 JSON, `pubspec.yaml` assets 에 `- assets/content/en/` 추가.
3. `android/app/src/main/res/values-en/strings.xml`, `Info.plist` 의 `CFBundleLocalizations` 에 `en`.
   iOS 권한 문구(`NSHealthShareUsageDescription`)는 Xcode 에서 `InfoPlist.strings` 를 언어별로 만든다.
4. 글꼴: 라틴 문자는 지금 글꼴(Noto Sans KR 서브셋)에 들어 있다. 일본어·중국어는 글꼴을 더하고
   `tools/subset_fonts.py` 를 다시 돌린다 (arb 파일의 글자도 읽는다).
5. `keepAll()` 은 한국어에서만 동작하므로 따로 할 일 없다. 영어·독일어는 30~50% 길어지니 버튼·시트 레이아웃을 확인한다.

번역 작업은 구글 시트·Crowdin·Lokalise 등에서 하고 ARB 로 내보내는 방식을 권한다 (ARB 를 바로 지원한다).
