# 꾸미기 파츠 — 차수 진행

한 차수는 네 단계를 돈다. 사용자가 지금 어느 단계를 말하는지 보고 그 단계부터 한다.

1. Codex 프롬프트 → 2. Codex 결과 검수 → 3. 에뮬레이터 확인 → 4. 커밋 (요청받았을 때만)

무엇을 어떻게 그리고 넣는지는 두 문서가 정본이다. 여기에 옮겨 적지 않는다.

- [docs/커스터마이징_파츠_발주서.md](../../../docs/커스터마이징_파츠_발주서.md) — 차수별 아이템 표, 프롬프트, 자리·크기 기준
- [docs/부처님_리소스_파이프라인.md](../../../docs/부처님_리소스_파이프라인.md) — 굽기 절차, `PLACED`·`FACE_FIT`, 숨길 곳, 살 경계

## 1. Codex 프롬프트

Codex에는 `bucheo-avatar-parts` 스킬이 깔려 있다(`~/.codex/skills/bucheo-avatar-parts`). 저장소의 `.codex/skills/bucheo-avatar-parts/`가 그 사본이다. 한쪽을 고치면 다른 쪽에도 복사한다. 생성·등록·검증·보고 형식은 그 스킬이 정한다. 그래서 프롬프트는 짧게 두 부분만 쓴다.

```markdown
$bucheo-avatar-parts 로 발주서 {N}차({슬롯} {개수}종)를 진행해 주세요.

이번 차수에서 특히 볼 것:
- (아래 표에서 이 차수에 해당하는 것)
```

발주서 해당 차수 표를 읽고, 그 차수만의 위험을 「특히 볼 것」에 적는다. 지금까지 쌓인 것:

| 슬롯 | 특히 볼 것 |
|---|---|
| 얼굴 | 비니 쓴 머리 위에서도 합성. 백호(이마 가운데 점)를 가리지 않는지. 한쪽 눈만 덮는 것은 베이스 기준점이 그 눈 |
| 입 | 입술·피부를 그리지 않았는지(재질을 입으면 둘레만 살빛으로 남는다). 선글라스 아래 테와 부딪히는지. 핑크 재질 흉내 합성. `popped:`는 풍선껌 전용 |
| 목 | 합장한 손 **앞**이 아니라 뒤로 지나가는지(`"hands"`). 펜던트가 손끝 y 514 위. 목에 거는 물건을 얼굴 피하려고 가슴까지 내리지 말 것(목베개가 손 앞에 떠 있었다). 기존 그림의 색 변형은 GPT로 다시 그리지 말고 PIL로 — 흰·회색 부분은 색상 회전으로 안 바뀌니 밝기를 살려 물들인다. 목둘레가 턱 위로 올라오면 `"chin"`으로 턱 뒤로 숨긴다 |
| 발 | 가사 5종 모두에서 밑단이 신발을 덮는지. 밑창 아래로 어두운 띠(`SHOE_GAP_SHADOW`)가 보이면 신발이 너무 높다. 발 비침 빌드 검사를 느슨하게 바꾸지 말 것 |
| 대좌 | 발바닥 아래 캔버스가 약 100px — 아래로 잘리지 않는지. 대좌는 몸 뒤 |
| 후광 | 모자를 써도 보이는지(링은 중심 (510, 356), 안쪽 지름이 비니 폭 470 보다 넓게). 머리 **위**는 100px 뿐이라 작아지고 모자에 가린다 — 링이 아닌 것은 머리 옆 위 빈자리(삿갓 챙 x 231~792 밖)에. 납작한 그림은 비율을 정해 받는다. 움직임(회전)은 넣지 말고 멈춘 그림까지 |
| 머리 | `--measure` 비침, 모자별 살 경계(`HAT_ERODE`·`FOREHEAD_SEAM`), `skin:` 등록, 핑꾸·돌·옥 재질 |
| 가사 | 실루엣이 같은지, 무늬 가사의 가사 영역 고르기, `MIN_BODY_SKIN` |

Codex 쪽 스킬이 없거나 사용자가 긴 프롬프트를 원하면 발주서 맨 아래 「Codex에 전달할 프롬프트」를 그 차수로 채워 준다.

## 2. Codex 결과 검수

사용자가 Codex 완료 보고를 붙이면:

1. **비교표를 연다.** 보고에 적힌 경로의 합성 이미지를 Read 로 본다. 자리, 가림(눈·입선·백호·손), 재질 합성에서 살빛 잔여를 본다.
2. **diff 를 본다.** `tools/build_avatar_assets.py`, `tools/make_avatar_thumbs.py`, `lib/features/avatar/avatar_equip.dart`, `test/avatar_test.dart`.
   - `kWardrobe`의 id·이름·슬롯·공덕이 발주서 표와 같은지
   - `PLACED` 위 주석에 조정 이유가 아이템마다 있는지
   - 테스트 변경이 「전부 껴입으면」의 **슬롯 마지막 아이템** 교체뿐인지. 다른 기대값을 바꿨으면 이유를 묻는다
3. **요청 밖 변경을 찾는다.** 이번 차수 아이템이 아닌 줄(기존 아이템의 배율, `OVERLAYS`·`ITEMS` 목록, 기존 webp 수정)이 있으면 보고서에 없어도 짚는다. 예전에 후광(`halo_ring`)이 이렇게 1.4배로 바뀌어 들어왔다. 전·후를 같은 조건으로 합성해 보여 주고, 유지할지 사용자가 정하게 한다.
4. `git status`로 새 파일이 아이템마다 세 개(`Imgs/*.png`, `assets/avatar/*.webp`, `assets/avatar/thumbs/*.webp`)인지 본다.

## 3. 에뮬레이터 확인

**새 에셋은 핫 리로드·핫 리스타트로 안 잡힌다.** 코드(옷장 목록)만 바뀌어 「목록은 있는데 그림이 없는」 상태가 되고, 화면에 `Unable to load asset ... Asset not found`가 뜬다. 사용자가 이걸 보고하면 코드를 의심하기 전에 다시 빌드한다.

```
flutter: C:\src\flutter\bin   (PATH 에 없다)
adb:     %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe
기기:    emulator-5554
패키지:  com.studiobh.bucheo_handsome
```

`flutter build apk --debug` → `adb install -r` → `am force-stop` → `monkey -p <패키지> -c android.intent.category.LAUNCHER 1`. 덮어쓰기 설치라 공덕·산 아이템은 남는다.

- 옷장: 하단 두 번째 탭 → 슬롯 칩. 썸네일과 가격이 나오는지 본다.
- **잠긴 아이템을 누르면 공덕으로 사는 창이 뜬다.** 사용자에게 묻지 않고 사지 않는다. 이미 가진 것만 눌러 미리 입혀 본다.
- 「이대로 입는다」는 누르지 않는다(사용자의 착용 상태가 바뀐다).
- 스와이프를 크게 하면 앱이 뒤로 내려갈 때가 있다. 슬롯 칩은 탭, 목록은 짧게 스와이프한다.

## 4. 커밋

사용자가 커밋을 요청할 때만 한다.

- 차수마다 한 커밋. 요청 밖 변경(예: 후광 수정)은 따로 커밋한다.
- 같은 파일에 여러 차수가 섞여 있으면 작업 파일은 건드리지 않고, 커밋 시점의 파일 내용을 따로 만들어 스테이징한다.
  ```
  h=$(git hash-object -w --path=<경로> <중간 단계 파일>)
  git update-index --cacheinfo 100644,$h,<경로>
  ```
  중간 단계 파일은 최종본에서 다른 차수 줄만 뺀 것. 만든 뒤 HEAD 와 diff 해서 그 차수 줄만 다른지 확인한다. 마지막 커밋 뒤 작업 파일이 깨끗한지 `git status`로 본다.
- 다른 작업(소리, 세션 화면, `docs/ReferenceImgs/` 등)은 빼고 파일을 이름으로 골라 담는다.
- 메시지: `꾸미기: {슬롯} 아이템 {개수}종 추가 (파츠 발주 {N}차)` + 아이템 이름 한 줄.
- 푸시는 사용자가 요청했을 때.
